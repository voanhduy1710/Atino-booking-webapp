# Atino Booking Webapp — Project Description

## Overview

A delivery booking system for Atino's distribution warehouse. Suppliers (NCC — Nhà Cung Cấp) register accounts, book delivery appointments, and view their own booking history. Warehouse reviewers validate bookings. Warehouse receivers scan QR codes on delivery day. Managers view all data and reports.

---

## Glossary

| Vietnamese | English | Meaning in this app |
|---|---|---|
| NCC / Nhà Cung Cấp | Supplier | The party delivering goods to Atino |
| Mã NCC | Supplier code | Identifier assigned by admin after account approval (e.g. `GC01`) |
| Kho | Warehouse | Atino distribution warehouse — expandable list |
| Đơn hàng / PO | Purchase Order | One row in the delivery table; one product/process the supplier is delivering |
| Mã sản phẩm — Mã quy trình | Product Code — Process Code | Composite identifier typed by supplier (e.g. `3466 - 15690-TH002`) |
| Số lần giao | Delivery round | Sequence: 1st, 2nd, ..., final ("cuối") |
| Phiếu giao | Delivery slip | Physical document photographed at booking time |
| Hóa đơn VAT | VAT invoice | Required photo on the **1st delivery round** of any PO |
| Số kiện/thùng | Boxes / cartons | Physical packaging count being delivered this round |
| Khung giờ | Time slot | One of 4 fixed delivery windows |
| Mã booking | Booking code | System-generated — format: `{YYYY-MM-DD}-{supplier_code}-{UniqueNumber}` |
| Ngày N+1 / N+2 | Day N+1 / N+2 | Delivery date relative to submission time |
| Ghi chú | Note / Remark | Free-text field the supplier fills for any special instructions |

## Supplier Account Lifecycle

Suppliers must have an approved account before they can submit bookings.

```
1. Supplier fills registration form:
   - Full name, username, password, confirm password, supplier code (Mã NCC)
   
2. Account created with status = 'pending'
   - Supplier cannot log in or submit until approved

3. Admin reviews pending registrations in /admin → Account tab
   - Approves: links account to the matching supplier_id in suppliers table, status → 'active'
   - Rejects: status → 'rejected', optional reason shown to supplier

4. Supplier can now log in and submit bookings
5. All bookings are tied to the supplier's account (viewable in "Lịch sử đặt hàng")
```

## Booking Registration Form

After logging in, the supplier fills **Đơn Đăng Ký — Giao Theo Đơn Hàng**:

### Section I — Thông Tin Nhà Cung Cấp

| # | Field | Behaviour |
|---|---|---|
| 1 | Cửa hàng (Store) | Dropdown from `warehouses` table |
| 2 | Mã NCC (Supplier Code) | Read-only — pulled from the supplier's account record |
| 3 | Tên NCC (Supplier Name) | Read-only — auto-filled from account |
| 4 | Ngày đăng ký giao hàng | Display-only — before 18:00 ICT → N+1; at or after 18:00 → N+2 (server-enforced) |
| 5 | Số lượng đơn hàng | Integer 1–99; drives how many PO rows are rendered |
| 6 | Đơn hàng (PO table) | Dynamic rows — one per PO (see PO Row table below) |

**PO Row columns:**

| Column | Type | Notes |
|---|---|---|
| STT | Auto | Row number |
| Mã sản phẩm — Mã quy trình | Text | Free text; supplier types the code |
| Số lần giao | Select | 1, 2, ..., cuối |
| Hóa đơn VAT | File upload | **Shown only when Số lần giao = 1**; mandatory |
| Tổng số kiện/thùng đi giao | Integer | Quantity for this round |
| Hình ảnh phiếu giao | Multi-file upload | ≥ 1 photo; up to 10 per row |

### Section II — Thông Tin Vận Chuyển

| # | Field | Behaviour |
|---|---|---|
| 7 | Khung giờ | One of: 07:00–09:00 / 09:00–11:00 / 13:30–15:30 / 15:30–17:00 |
| 8 | Ghi chú (Notes) | Free-text — supplier inputs any special delivery instructions |
| 9 | Ghi chú giao hàng (Atino notice) | Pre-filled standard Atino text (read-only display) |

**After successful submission:**
- Booking code generated: `{YYYY-MM-DD}-{supplier_code}-{UniqueNumber}` (e.g. `2026-05-04-GC01-3434657`)
- QR code displayed encoding `https://[app-host]/booking/{booking_token}`
- Booking enters status **`pending`**
- Supplier can view this booking in **Lịch sử đặt hàng**

## Supplier — My Bookings (Lịch Sử Đặt Hàng)

Each supplier sees only their own bookings. Features:
- Table: booking code, delivery date, time slot, warehouse, status badge, submitted at
- Click row → detail drawer with full PO list, photos, reviewer notes, received quantities
- Status updates and reviewer rejection reasons are visible here

---

## Booking State Machine

```
[pending] ──confirm any item──→ [confirmed] ──receive──→ [received]
    │
    └──reject all items──→ [rejected]
```

| State | Set by | Visible to supplier as |
|---|---|---|
| `pending` | Supplier (on submit) | "Đang chờ xác nhận" |
| `confirmed` | Reviewer | "Đã xác nhận — chờ giao hàng" |
| `rejected` | Reviewer | "Đã từ chối" + reason |
| `received` | Receiver | "Đã nhận hàng" |

---

## Reviewer Flow (Lê Thiên Tình)

- Logs in at `/login` with account `lethientinh`
- Redirected to `/reviewer` dashboard
- Views all pending bookings in a table (auto-refreshes every 30s)
- Opens a booking → sees all PO items with photos
- Per item: **Xác nhận** (confirm) or **Từ chối** (reject, with reason)
- Partial approval allowed: confirms 3 of 5 POs → booking → `confirmed`; supplier notified

---

## Receiver Flow (Lê Thiên Dũng)

- Logs in with account `lethiendung`
- Redirected to `/receiver`
- Scans QR or types booking code
- Sees **only confirmed PO items**
- Enters actual quantities received per row
- Can upload photos of any discrepancy
- Submits → booking → `received`; discrepancies logged for manager

---

## Manager Flow (Lê Thị Hồng)

- Logs in with account `lethihong`
- Redirected to `/manager`
- All-bookings table with filter/sort/paginate
- Reports tab: aggregated views (by date, supplier, status, discrepancy)
- Drill into individual bookings and photos
- CSV export
- Data retained indefinitely

---

## Admin Page (`/admin`)

Hidden route — client-side only, no backend guard. Accessible only with the `admin` account.

Tabs:
- **Thông tin dự án** (default) — project info panel, shows logged-in username
- **Tài khoản** — pending supplier registrations; approve (+ link to supplier code) or reject
- **Nhà cung cấp** — manage `suppliers` master data (add/edit/deactivate supplier codes + names)
- **Kho hàng** — manage `warehouses` table (add/edit warehouses)
- **Nhân viên** — view active staff accounts

## Notification System

A bell icon in the navbar on all authenticated pages. Unread badge count shown.

| Event | Who is notified |
|---|---|
| Booking submitted | Reviewer (Lê Thiên Tình) |
| Booking confirmed | Supplier |
| Booking rejected (with reason) | Supplier |
| Booking received | Supplier, Manager |
| Discrepancy recorded | Manager |
| Supplier account pending approval | Admin |
| Supplier account approved | Supplier |

In-app notifications stored in a `notifications` table. No email/SMS in v1.

---

## Booking Code Format

Format: `{YYYY-MM-DD}-{supplier_code}-{UniqueNumber}`

Example: `2026-05-04-GC01-3434657`

- **YYYY-MM-DD** prefix → lexicographic sort = chronological sort
- **supplier_code** → immediately identifies which supplier
- **UniqueNumber** → 7-digit random integer (padded), collision-checked at insert

This format is human-readable at the warehouse gate and sortable in exports.

## Edge Cases & Business Rules

| Situation | Behaviour |
|---|---|
| Submit at exactly 18:00:00 ICT | Treated as "at or after" → N+2 |
| Weekend / holiday N+1 | Calendar days only — no skipping |
| Supplier account pending / rejected | Cannot log in or submit |
| Supplier code inactive after account was approved | Booking rejected at submit with clear error |
| Receiver scans a `pending` booking | "Booking chưa được xác nhận" |
| Receiver scans a `received` booking | "Booking đã nhận hàng trước đó" |
| Receiver scans a `rejected` booking | "Mã booking không hợp lệ" |
| Quantity received ≠ quantity booked | Discrepancy logged; visible to manager |
| Supplier re-delivery request (post-submit) | Supplier can flag booking for amendment; reviewer confirms or denies the request |
| No daily capacity hard cap | No unit cap enforced — reviewer decides |
