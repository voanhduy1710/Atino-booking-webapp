## Feature Folder Convention

```
src/
  features/
    booking/          ← supplier booking form + submission
    warehouse/        ← QR scan + receiving flow
    manager/          ← dashboard + reports
    auth/             ← login for all roles
  shared/
    components/       ← truly reusable UI primitives
    hooks/            ← shared hooks
    lib/              ← supabase client, utils
    types/            ← shared TypeScript types
```

Each feature folder contains its own:
- `components/`
- `hooks/`
- `services/` (API calls)
- `types.ts`

Do not mix feature concerns. If a component is only used in one feature, it belongs in that feature's `components/` directory.

## Key Business Logic Locations

| Logic | Where to implement |
|---|---|
| Delivery date calculation (N+1 / N+2) | Server-side in a Supabase edge function or DB trigger |
| Daily capacity check (20,000 units) | DB-level check or server-side before confirmation |
| Booking code generation | Server-side — unique, sequential or UUID-based |
| QR code rendering | Client-side using a QR library (e.g., `qrcode.react`) |
| RLS policies | Supabase dashboard / migration files |

## Form Behavior Notes

- When the supplier selects **6 POs**, the form must render exactly 6 PO rows dynamically.
- Each PO row contains: product/process code, delivery round selector, quantity input, photo upload.
- On **1st delivery round selection** for any PO row, an additional VAT invoice upload field must appear inline in that row.
- The delivery note text area is pre-filled with Atino's standard message and should be read-only or editable but always shown.

---

## Booking Confirmation Screen

After successful form submission:
1. Display a large QR code (generated from the booking URL or code)
2. Display the booking code as plain text below (e.g., `Mã đăng ký: 80072601100032`)
3. Display booking type label (e.g., `Loại đăng ký: Giao theo đơn hàng (Outright)`)
4. Supplier should be able to screenshot or print this page

---

## Image Upload Behavior

- Multiple images per PO row (delivery slip photos)
- Single mandatory image per PO row on 1st delivery (VAT invoice)
- Images go to Supabase Storage, not DB columns
- Store only the storage path/URL in the DB
- Accept: jpg, jpeg, png, pdf
- Max size per file: 10MB (TBD — confirm with user)

## Do Not Do

- Do not add features beyond what the task specifies.
- Do not generate mock data in production code paths.
- Do not commit schema changes without a migration file.
- Do not hardcode supplier codes or warehouse names in the frontend — these come from the DB.
- Do not use direct SQL in the frontend — use Supabase client methods.
- Do not skip RLS. Every table must have RLS enabled with explicit policies per role.
