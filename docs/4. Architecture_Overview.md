# Architecture Overview

## High-Level Stack

| Layer | Technology |
|---|---|
| Frontend | React + Vite (feature-based SPA) |
| Styling | Tailwind CSS — black/white palette |
| Tables | TanStack Table v8 |
| Database | Supabase (PostgreSQL + Storage + Auth) |
| Hosting | Google Cloud Run |
| QR Code | `qrcode.react` (client-side generation) |

## Auth & Access Control

Supabase Auth handles authentication. Row Level Security (RLS) enforces access:

| Role | Access |
|---|---|
| Supplier | Can create bookings, view their own bookings only |
| Warehouse Reviewer | Can read all bookings, update `booking_items.status` |
| Warehouse Receiver | Can read confirmed bookings, update `quantity_received` |
| Manager | Full read on all tables |

---

## Key Flows

### Supplier Submits Booking
1. Supplier fills form → client validates
2. POST to Supabase: insert `bookings` + `booking_items` + upload photos to Storage
3. Server calculates `delivery_date` (N+1 or N+2 based on `submitted_at`)
4. System generates `booking_code`
5. Confirmation screen renders QR + code

### Warehouse Reviewer Confirms
1. Reviewer opens pending bookings list (manager/warehouse view)
2. For each `booking_item`: sets status to `confirmed` or `rejected`
3. Once confirmed, system opens delivery slot for N+1

### Warehouse Receives
1. Staff scans supplier's QR code
2. App fetches booking by code, displays only `confirmed` PO items
3. Staff enters `quantity_received` per PO line
4. Submit → records receive timestamp + staff ID

## Delivery Date Logic

```ts
function calculateDeliveryDate(submittedAt: Date): Date {
  const cutoff = new Date(submittedAt);
  cutoff.setHours(18, 0, 0, 0);
  const daysToAdd = submittedAt < cutoff ? 1 : 2;
  const deliveryDate = new Date(submittedAt);
  deliveryDate.setDate(deliveryDate.getDate() + daysToAdd);
  return deliveryDate;
}
```

This logic is enforced server-side (Supabase function or DB trigger) — the client only displays the calculated date.

## File Storage

- Supabase Storage bucket: `booking-attachments`
- Path pattern: `/{booking_id}/{item_id}/{filename}`
- Accepted types: jpg, jpeg, png, pdf
- Max size: 10MB per file
- Access: private bucket — URLs are signed/short-lived when served to client

## Scalability Notes

- ~50 concurrent users → Cloud Run with 1–2 instances is sufficient
- No WebSocket/realtime needed for initial release — polling or manual refresh is acceptable
- TanStack Table handles client-side sorting/filtering — avoids unnecessary DB round trips for small datasets
- All heavy queries (manager reports) should use Supabase views or RPC functions, not raw client-side joins
