# Architecture Overview

## High-Level Stack

| Layer | Choice |
|---|---|
| Frontend | React 18 + TypeScript (strict) + Vite |
| Routing | React Router v6 |
| Server state | TanStack Query v5 |
| Forms | React Hook Form + Zod |
| Tables | TanStack Table v8 |
| Styling | Tailwind CSS (black/white palette) |
| QR generation | `qrcode.react` |
| QR scanning | `@zxing/browser` (or `html5-qrcode`) |
| Database / Auth / Storage | Supabase (Postgres + Auth + Storage + Edge Functions) |
| Hosting | Google Cloud Run |
| Time zone | `Asia/Ho_Chi_Minh` (ICT, UTC+7) — anchored via `date-fns-tz` |

## Database Schema

All tables in the `public` schema. RLS enabled on every table.

### `suppliers`
| Column | Type | Constraints |
|---|---|---|
| `id` | uuid | PK, default `gen_random_uuid()` |
| `code` | text | UNIQUE, NOT NULL — e.g. `GC01` |
| `name` | text | NOT NULL |
| `active` | boolean | NOT NULL, default `true` |
| `created_at` | timestamptz | NOT NULL, default `now()` |

Index: `(code) WHERE active = true`.

### `staff`
| Column | Type | Constraints |
|---|---|---|
| `id` | uuid | PK — matches `auth.users.id` |
| `name` | text | NOT NULL |
| `role` | enum `staff_role` | NOT NULL — `warehouse_reviewer`, `warehouse_receiver`, `manager` |
| `active` | boolean | NOT NULL, default `true` |
| `created_at` | timestamptz | NOT NULL, default `now()` |

### `bookings`
| Column | Type | Constraints |
|---|---|---|
| `id` | uuid | PK, default `gen_random_uuid()` |
| `booking_code` | text | UNIQUE, NOT NULL — generated by trigger |
| `booking_token` | uuid | UNIQUE, NOT NULL, default `gen_random_uuid()` — opaque public link |
| `supplier_id` | uuid | FK → `suppliers(id)`, NOT NULL |
| `warehouse` | text | NOT NULL — currently `'Kho Tân Hoàng Long'` |
| `delivery_date` | date | NOT NULL — set by trigger from `submitted_at` |
| `time_slot` | enum `time_slot` | NOT NULL — `'07-09'`, `'09-11'`, `'13-15'`, `'15-17'` |
| `delivery_note` | text | NOT NULL |
| `status` | enum `booking_status` | NOT NULL, default `'pending'` — `pending`, `confirmed`, `rejected`, `received` |
| `submitted_at` | timestamptz | NOT NULL, default `now()` |
| `confirmed_by` | uuid | FK → `staff(id)`, NULL until reviewer acts |
| `confirmed_at` | timestamptz | NULL |
| `received_by` | uuid | FK → `staff(id)`, NULL until receiver scans |
| `received_at` | timestamptz | NULL |

Indexes: `(delivery_date)`, `(status)`, `(supplier_id, submitted_at DESC)`, `(booking_code)`, `(booking_token)`.

### `booking_items`
| Column | Type | Constraints |
|---|---|---|
| `id` | uuid | PK, default `gen_random_uuid()` |
| `booking_id` | uuid | FK → `bookings(id)` ON DELETE CASCADE, NOT NULL |
| `product_code` | text | NOT NULL |
| `process_code` | text | NOT NULL |
| `delivery_round` | int | NOT NULL, CHECK ≥ 1 |
| `is_final_round` | boolean | NOT NULL, default `false` — represents "lần cuối" |
| `quantity_booked` | int | NOT NULL, CHECK ≥ 1 |
| `quantity_received` | int | NULL until receiver records |
| `status` | enum `booking_item_status` | NOT NULL, default `'pending'` — `pending`, `confirmed`, `rejected` |
| `vat_invoice_url` | text | NULL — required iff `delivery_round = 1` (DB check) |
| `reject_reason` | text | NULL — populated when reviewer rejects |

Constraint: `CHECK (delivery_round != 1 OR vat_invoice_url IS NOT NULL)`.
Index: `(booking_id)`, `(status)`.

### `booking_item_photos`
| Column | Type | Constraints |
|---|---|---|
| `id` | uuid | PK, default `gen_random_uuid()` |
| `booking_item_id` | uuid | FK → `booking_items(id)` ON DELETE CASCADE, NOT NULL |
| `storage_path` | text | NOT NULL — e.g. `/{booking_id}/{item_id}/slip-1.jpg` |
| `uploaded_at` | timestamptz | NOT NULL, default `now()` |

Index: `(booking_item_id)`.

### `daily_capacity` (optional materialized view)
A view aggregating confirmed `quantity_booked` per `delivery_date`, used by the manager widget and the cap-check RPC.

```sql
CREATE VIEW daily_capacity AS
SELECT
  b.delivery_date,
  SUM(bi.quantity_booked) FILTER (WHERE bi.status = 'confirmed') AS confirmed_units,
  20000 - SUM(bi.quantity_booked) FILTER (WHERE bi.status = 'confirmed') AS remaining_units
FROM bookings b
JOIN booking_items bi ON bi.booking_id = b.id
GROUP BY b.delivery_date;
```

## Key DB Functions / Triggers

### `set_booking_delivery_date()` — trigger on `bookings` BEFORE INSERT
Sets `delivery_date` based on `submitted_at` ICT:
```sql
DECLARE submitted_ict timestamp;
BEGIN
  submitted_ict := NEW.submitted_at AT TIME ZONE 'Asia/Ho_Chi_Minh';
  IF EXTRACT(HOUR FROM submitted_ict) < 18 THEN
    NEW.delivery_date := (submitted_ict + INTERVAL '1 day')::date;
  ELSE
    NEW.delivery_date := (submitted_ict + INTERVAL '2 days')::date;
  END IF;
  RETURN NEW;
END;
```

### `generate_booking_code()` — trigger on `bookings` BEFORE INSERT
Produces a 14-digit numeric code unique across the table. Format TBD — see Open Questions.

### `transition_booking_status(p_booking_id uuid, p_action text)` — RPC
Validates allowed transitions:
- `confirm` from `pending` (if any item confirmed)
- `reject` from `pending` (if all items rejected)
- `receive` from `confirmed`

### `confirm_booking_item(p_item_id uuid)` — RPC
- Verifies caller has `warehouse_reviewer` role
- Locks the relevant `delivery_date` row
- Checks `daily_capacity.remaining_units >= booking_items.quantity_booked`
- If pass: sets `status = 'confirmed'`, returns success
- If fail: returns capacity error; reviewer must defer the item

### `receive_booking(p_booking_token uuid, p_quantities jsonb)` — RPC
- Verifies caller has `warehouse_receiver` role
- Verifies booking is in `confirmed`
- Updates `quantity_received` for each confirmed item
- Sets `bookings.status = 'received'`, `received_by`, `received_at`

## Edge Functions

### `finalize_booking`
Called by the supplier flow after the form is submitted. Runs in a single transaction:
1. Insert `bookings` row (triggers fire to set `delivery_date`, `booking_code`)
2. Insert `booking_items` rows
3. Insert `booking_item_photos` rows
4. Move uploaded files from `/temp/{session_id}/...` to `/{booking_id}/{item_id}/...`
5. Return `{ booking_code, booking_token }` to the client

### `cleanup_temp_uploads`
Scheduled (cron, every hour). Deletes files in `booking-attachments/temp/` older than 24 hours.

## Auth & Access Control

Supabase Auth handles staff/manager logins. Suppliers are **not authenticated** — the booking form is public.

### RLS Summary

| Table | Public (anon) | warehouse_reviewer | warehouse_receiver | manager |
|---|---|---|---|---|
| `suppliers` | SELECT (active only) | SELECT | SELECT | SELECT/INSERT/UPDATE |
| `bookings` | INSERT (via Edge Function only); SELECT by `booking_token` | SELECT all; UPDATE status via RPC | SELECT confirmed; UPDATE via RPC | SELECT all |
| `booking_items` | INSERT (via Edge Function); SELECT by `booking_token` (joined) | SELECT all; UPDATE status via RPC | SELECT confirmed; UPDATE qty_received via RPC | SELECT all |
| `booking_item_photos` | INSERT (via Edge Function) | SELECT all | SELECT confirmed | SELECT all |
| `staff` | (no access) | SELECT self | SELECT self | SELECT/INSERT/UPDATE |

Notes:
- Anon SELECT on `bookings` requires the `booking_token` to match — used so the QR-scanned link works without auth (read-only)
- All anon writes go through `finalize_booking` Edge Function, which uses the service role key server-side
- RPCs (`confirm_booking_item`, `receive_booking`, `transition_booking_status`) are `SECURITY DEFINER` so they can enforce role checks via JWT claims

## State Machines

### Booking
```
[pending] ──confirm──→ [confirmed] ──receive──→ [received]
    │
    └─reject─→ [rejected]
```

### Booking Item (independent within a booking)
```
[pending] ──confirm──→ [confirmed]
    │
    └─reject─→ [rejected]
```

A booking is **confirmed** if ≥ 1 item is confirmed. **Rejected** only if **all** items are rejected.

## File Storage

- **Bucket:** `booking-attachments` (private)
- **Final path:** `/{booking_id}/{item_id}/{filename}`
- **Temp path:** `/temp/{session_id}/{filename}` (pre-submit)
- **Allowed types:** jpg, jpeg, png, pdf
- **Max size:** 10 MB / file
- **Read access:** signed URLs (expiry 1 hour) generated server-side / via authorized client
- **Cleanup:** `cleanup_temp_uploads` Edge Function deletes orphaned `/temp/*` after 24h

## Performance & Scale Notes

- Target ~50 concurrent users — Cloud Run min-instances 1, max 3.
- Cold start mitigated by min-instances = 1.
- Pagination on every table (default 50, max 200).
- No realtime subscriptions in v1; reviewer dashboard polls every 30s via TanStack Query `refetchInterval`.
- Heavy aggregations (capacity widget, manager reports) run in DB views or RPCs — never N+1 in client code.
- Image CDN: Supabase Storage's signed URLs are sufficient at this scale.
- Vite build emits hashed assets; Cloud Run serves with long-cache headers.
