## FLOW A — Supplier Booking Registration

```
[Đăng ký giao hàng] clicked  →  /booking/new
│
├─ Step 1: Page Init IN PARALLEL
│         │
│         ├─── Load Supplier Master Data
│         │         GET   supabase: SELECT id, code, name
│         │                         FROM suppliers WHERE active = true
│         │                         ORDER BY code
│         │              └─ Cached via TanStack Query (staleTime: 10 min)
│         │              └─ Populates "Mã NCC" dropdown
│         │
│         └─── Init Form State (React Hook Form)
│                   ├─ warehouse        = "Kho Tân Hoàng Long" (read-only)
│                   ├─ delivery_note    = standard Atino notice
│                   ├─ time_slot        = unset
│                   ├─ supplier_id      = unset
│                   ├─ po_count         = unset
│                   └─ items            = [] (will be field-array of length po_count)
│
├─ Step 2: Section I — Thông Tin Nhà Cung Cấp
│         │
│         ├─── Cửa hàng (Store)
│         │         Pre-filled, read-only
│         │
│         ├─── Mã NCC dropdown → onChange
│         │         └─ Sets supplier_id; "Tên NCC" auto-fills from cached supplier list
│         │
│         ├─── Tên NCC
│         │         Read-only, derived
│         │
│         ├─── Ngày đăng ký giao hàng (display only)
│         │         CLIENT-SIDE PREVIEW (informational):
│         │           IF now ICT < 18:00 → show "today + 1"
│         │           ELSE                → show "today + 2"
│         │         (Authoritative value computed server-side at insert)
│         │
│         ├─── Số lượng đơn hàng (po_count)
│         │         Integer 1–99 → onChange triggers field array resize
│         │
│         └─── PO Table — dynamic rows (TanStack Table render of useFieldArray)
│                   │
│                   Per row (one per PO):
│                   ├─ Mã sản phẩm — Mã quy trình  (text inputs, required)
│                   ├─ Số lần giao select  → 1 | 2 | ... | "cuối"
│                   │     │
│                   │     └─ IF round = 1 selected:
│                   │              Render inline: Hóa đơn VAT (single file upload, REQUIRED)
│                   │              UPLOAD on file pick →
│                   │                  supabase.storage
│                   │                    .from('booking-attachments')
│                   │                    .upload(`temp/${session_id}/vat_${item_idx}.${ext}`, file)
│                   │              Save returned path to form state (not yet in DB)
│                   │
│                   ├─ Tổng số kiện/thùng đi giao  (integer ≥ 1, required)
│                   │
│                   └─ Hình ảnh phiếu giao  (multi-file upload, ≥ 1 required, max 10)
│                          UPLOAD on each file pick →
│                              supabase.storage.upload(`temp/${session_id}/slip_${item_idx}_${n}.${ext}`)
│                          Track each path in form state
│
├─ Step 3: Section II — Thông Tin Vận Chuyển
│         │
│         ├─── Khung giờ select (required)
│         │         '07-09' | '09-11' | '13-15' | '15-17'
│         │
│         └─── Ghi chú giao hàng (textarea)
│                   Pre-filled with standard text; user may edit
│
├─ Step 4: Submit
│         │
│         ├─── Client-side validation (Zod schema via React Hook Form)
│         │         ├─ All required fields present
│         │         ├─ Each PO row has ≥ 1 delivery slip photo
│         │         ├─ If any row has round=1, VAT invoice path is set
│         │         └─ FAIL → show inline errors, block submit
│         │
│         └─── PASS → Call Edge Function
│                   │
│                   POST  /functions/v1/finalize_booking
│                   Body: {
│                     supplier_id, time_slot, delivery_note,
│                     items: [
│                       { product_code, process_code, delivery_round,
│                         is_final_round, quantity_booked,
│                         vat_invoice_temp_path, slip_temp_paths: [...] }, ...
│                     ],
│                     session_id
│                   }
│                   │
│                   Edge Function (uses service role) executes:
│                   │
│                   ├─ 1. INSERT bookings
│                   │       Triggers fire:
│                   │         set_booking_delivery_date()  → fills delivery_date (N+1 / N+2 ICT)
│                   │         generate_booking_code()      → fills booking_code (14-digit unique)
│                   │       Returns: id, booking_code, booking_token, delivery_date
│                   │
│                   ├─ 2. INSERT booking_items (loop, transactional)
│                   │       Check constraint validates VAT invoice presence on round=1
│                   │       Returns: array of item ids
│                   │
│                   ├─ 3. Move uploaded files (storage)
│                   │       For each item, for each temp path:
│                   │           storage.move(`temp/${sid}/${file}`, `${booking_id}/${item_id}/${file}`)
│                   │       Update booking_items.vat_invoice_url = final path (where applicable)
│                   │
│                   ├─ 4. INSERT booking_item_photos (one row per slip photo per item)
│                   │       storage_path = final moved path
│                   │
│                   └─ 5. Return { booking_code, booking_token, delivery_date }
│
├─ Step 5: Booking Confirmation Screen  →  /booking/{token}/confirmation
│         │
│         ├─ Display booking_code (e.g. "Mã đăng ký: 80072601100032")
│         ├─ Display "Loại đăng ký: Giao theo đơn hàng (Outright)"
│         ├─ Render QR code (qrcode.react), encoding:
│         │       https://[app-host]/booking/{booking_token}
│         ├─ Print-friendly layout — supplier screenshots / prints
│         └─ Booking is now status='pending' awaiting reviewer
│
└─ ERROR PATHS (across the flow)
          ├─ Supplier code became inactive between page load and submit
          │     → Edge Function returns 422; UI shows "Mã NCC không hợp lệ"
          ├─ Capacity already at 20,000 for the resolved delivery_date?
          │     → Booking still accepted (cap is enforced at confirmation, not submission)
          ├─ Storage upload failure
          │     → Inline retry per file; submission disabled until all uploads succeed
          └─ Edge Function 5xx
                → Show toast; preserve form state; allow retry
```

## FLOW D — Warehouse Reviewer Dashboard (`warehouse_reviewer`)

```
Login → /reviewer
│
├─ Step 1: Load Pending Queue + Daily Capacity IN PARALLEL
│         │
│         ├─── Pending Bookings
│         │       GET   supabase RPC: get_pending_bookings()
│         │             SELECT b.*, s.name AS supplier_name
│         │             FROM bookings b
│         │             JOIN suppliers s ON s.id = b.supplier_id
│         │             WHERE b.status = 'pending'
│         │             ORDER BY b.delivery_date ASC, b.submitted_at ASC
│         │       Renders: TanStack Table (sortable, filterable)
│         │       Polls every 30s (TanStack Query refetchInterval)
│         │
│         └─── Daily Capacity Widget
│                 GET  supabase: SELECT * FROM daily_capacity
│                                WHERE delivery_date >= today
│                                ORDER BY delivery_date ASC LIMIT 7
│                 Shows confirmed_units / 20,000 per upcoming day
│
├─ Step 2: Reviewer opens a booking row
│         GET   supabase: SELECT bi.*, array_agg(p.storage_path) AS photos
│                         FROM booking_items bi
│                         LEFT JOIN booking_item_photos p ON p.booking_item_id = bi.id
│                         WHERE bi.booking_id = $id
│                         GROUP BY bi.id
│         For each photo: storage.createSignedUrl(path, 3600)
│         Modal renders PO list with thumbnails (click → full size)
│
├─ Step 3: Reviewer acts on each PO item
│         │
│         ├─── Confirm
│         │       POST  RPC: confirm_booking_item(p_item_id)
│         │             1. Verify caller role
│         │             2. Lock daily_capacity row for booking's delivery_date
│         │             3. Check remaining_units >= quantity_booked
│         │                ├─ FAIL: return error 'capacity_exceeded'
│         │                │       UI: "Đã đủ 20.000 hàng cho ngày này"
│         │                │       Item stays pending (reviewer can defer)
│         │                └─ PASS: UPDATE booking_items SET status = 'confirmed'
│         │
│         └─── Reject
│                 POST  RPC: reject_booking_item(p_item_id, p_reason)
│                       UPDATE booking_items
│                         SET status = 'rejected', reject_reason = p_reason
│
├─ Step 4: Finalize Booking Review
│         POST  RPC: transition_booking_status(p_booking_id, 'auto')
│               Logic:
│                 IF every item.status = 'rejected':
│                     UPDATE bookings SET status = 'rejected'
│                 ELSIF any item.status = 'confirmed':
│                     UPDATE bookings
│                       SET status = 'confirmed',
│                           confirmed_by = auth.uid(),
│                           confirmed_at = now()
│                 ELSE: leave pending (some items still pending)
│
└─ Outcome
          ├─ Confirmed bookings appear in receiver scan results for delivery_date
          ├─ Rejected: no further action; supplier may resubmit
          └─ Partially confirmed: only confirmed items will appear at receiving
```

## FLOW E — Warehouse Receiver Scan (`warehouse_receiver`)

```
Login → /receiver
│
├─ Step 1: Scan or Enter Booking Code
│         │
│         ├─── Scan QR (camera)
│         │       @zxing/browser decodes QR → extracts booking_token from URL
│         │
│         └─── Manual Input
│                 Type booking_code (14 digits) directly
│
├─ Step 2: Load Booking
│         GET   supabase: SELECT b.*, s.name AS supplier_name
│                         FROM bookings b
│                         JOIN suppliers s ON s.id = b.supplier_id
│                         WHERE b.booking_token = $token  (or booking_code = $code)
│
│         ├─ NOT FOUND or status='rejected'
│         │     → "Mã booking không hợp lệ"
│         │
│         ├─ status='pending'
│         │     → "Booking chưa được xác nhận. Vui lòng chờ xác nhận trước."
│         │
│         ├─ status='received'
│         │     → "Booking đã nhận hàng trước đó"
│         │
│         └─ status='confirmed'
│                 GET  supabase: SELECT * FROM booking_items
│                                WHERE booking_id = $id AND status = 'confirmed'
│                 Render: PO table with [quantity_received] input per row
│
├─ Step 3: Receiver enters actual quantities
│         Per confirmed PO item:
│         └─ quantity_received input (integer ≥ 0)
│         Optional: scan/photograph any discrepancies
│
└─ Step 4: Submit Receive Record
          POST  RPC: receive_booking(p_booking_token, p_quantities)
                where p_quantities = [{ item_id, quantity_received }, ...]
                1. Verify caller has warehouse_receiver role
                2. Verify booking.status = 'confirmed'
                3. UPDATE booking_items SET quantity_received = $qty per item
                4. UPDATE bookings
                     SET status = 'received',
                         received_by = auth.uid(),
                         received_at = now()
                5. Return summary

          UI: Show success screen with summary, including any discrepancies
              ("Số lượng thực nhận khác booking — NCC vẫn bị tính trễ hạn theo quy định")
```

## Supabase Storage Lifecycle

```
Photo Upload — supplier flow (pre-submit)
│
├─ User selects file in PoRow / VAT field
├─ Client uploads directly:
│     supabase.storage
│       .from('booking-attachments')
│       .upload(`temp/${session_id}/${filename}`, file)
├─ Store returned path in form state
└─ Show progress, allow retry, allow remove

On finalize_booking Edge Function success:
│
└─ Server moves: temp/{session_id}/* → {booking_id}/{item_id}/*
   booking_item_photos.storage_path / booking_items.vat_invoice_url updated to final path

Read by Reviewer / Manager UI:
│
└─ supabase.storage.from('booking-attachments')
     .createSignedUrl(path, 3600)
   Render <img src={signedUrl} />

Cleanup
│
└─ cleanup_temp_uploads (cron, hourly)
   Deletes temp/* older than 24 hours
```

## Status Transition Reference

```
booking.status
──────────────
pending  ──confirm_any_item──→ confirmed  ──receive──→ received
   │
   └────reject_all_items────→ rejected

booking_item.status
───────────────────
pending  ──confirm──→ confirmed
   │
   └─reject──→ rejected
```

| Trigger | Allowed transition | Enforced by |
|---|---|---|
| `confirm_booking_item` | item: pending → confirmed | RPC + capacity check |
| `reject_booking_item` | item: pending → rejected | RPC |
| `transition_booking_status('auto')` | booking: pending → confirmed/rejected based on items | RPC |
| `receive_booking` | booking: confirmed → received | RPC |

Disallowed transitions (e.g., received → pending, confirmed → rejected) are blocked at the RPC level and would return an error.
