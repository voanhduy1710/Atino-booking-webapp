## FLOW AUTH — Login & Supplier Registration

```
/login   (two-tab card)
│
├─ Tab: "Đăng nhập"
│         │
│         ├─ Input: username + password
│         └─ Submit
│                   POST  Edge Function: /auth/login
│                   Body: { username, password }
│                   │
│                   ├─ Edge Function: read AUTH_USERS env JSON
│                   │       Find entry where username matches
│                   │       bcrypt.compare(password, stored_hash)
│                   │       IF match:
│                   │           Issue JWT { sub, role, allowedRoutes, exp: +8h }
│                   │           Signed with JWT_SECRET
│                   │           Return { token, role }
│                   │       IF no match → 401 "Sai tên đăng nhập hoặc mật khẩu"
│                   │
│                   ├─ Supplier login (falls through to DB check if not in AUTH_USERS)
│                   │       SELECT sa.* FROM supplier_accounts sa
│                   │       WHERE sa.username = $username
│                   │         AND sa.status = 'active'
│                   │       bcrypt.compare(password, sa.password_hash)
│                   │       IF match:
│                   │           Issue JWT { sub, role:'supplier', supplier_id, exp: +8h }
│                   │           Return { token, role: 'supplier' }
│                   │       IF status = 'pending' → "Tài khoản chờ xác nhận"
│                   │       IF status = 'rejected' → "Tài khoản đã bị từ chối"
│                   │       IF not found → 401
│                   │
│                   └─ Frontend stores JWT in localStorage
│                       Route guard reads role → redirect:
│                           supplier            → /my-bookings
│                           warehouse_reviewer  → /reviewer
│                           warehouse_receiver  → /receiver
│                           manager             → /manager
│                           admin               → /admin
│
└─ Tab: "Đăng ký tài khoản"  (Supplier only)
          │
          ├─ Input: Họ và tên, Tên đăng nhập, Mật khẩu, Xác nhận mật khẩu, Mã NCC
          └─ Submit
                    POST  Edge Function: /auth/register-supplier
                    Body: { full_name, username, password, supplier_code_requested }
                    │
                    Edge Function:
                    ├─ Check username not already taken
                    │       IF taken → "Tên đăng nhập đã tồn tại"
                    ├─ Hash password: bcrypt(password, 12)
                    ├─ INSERT supplier_accounts
                    │       { username, password_hash, full_name,
                    │         supplier_code_requested, status='pending' }
                    └─ INSERT notification
                            { recipient_type='staff', recipient_id='voanhduy1710',
                              event_type='account_pending',
                              message='NCC mới đăng ký: [full_name]' }

          UI: "Đăng ký thành công. Vui lòng chờ admin xác nhận tài khoản."
```

## FLOW A — Supplier Booking Registration

```
Supplier logs in → /booking/new
│
├─ Step 1: Page Init IN PARALLEL
│         ├─── Load Warehouses
│         │       GET supabase: SELECT id, code, name FROM warehouses WHERE active = true
│         │       Populates "Cửa hàng" dropdown
│         │
│         └─── Load Supplier Info from JWT
│                 supplier_id decoded from JWT
│                 GET supabase: SELECT code, name FROM suppliers WHERE id = $supplier_id
│                 Pre-fills Mã NCC + Tên NCC (read-only)
│
├─ Step 2: Supplier Fills Section I — Thông Tin Nhà Cung Cấp
│         │
│         ├─ Cửa hàng dropdown (required)
│         ├─ Mã NCC — read-only from JWT
│         ├─ Tên NCC — read-only from JWT
│         ├─ Ngày đăng ký — preview only:
│         │       now ICT < 18:00 → show "tomorrow (N+1)"
│         │       now ICT ≥ 18:00 → show "day after (N+2)"
│         │       (Authoritative value set by DB trigger at insert)
│         ├─ Số lượng đơn hàng (1–99) → resizes PO row array
│         │
│         └─ PO Table (useFieldArray — N rows):
│                 Per row:
│                 ├─ Mã sản phẩm / Mã quy trình (text, required)
│                 ├─ Số lần giao select: 1 | 2 | ... | cuối
│                 │     └─ IF round = 1:
│                 │            Hóa đơn VAT upload appears inline (single file, required)
│                 │            UPLOAD immediately on pick:
│                 │                supabase.storage.upload(
│                 │                  `temp/${session_id}/vat_${row}.{ext}`, file)
│                 │            Store path in form state
│                 ├─ Tổng số kiện/thùng (integer ≥ 1, required)
│                 └─ Hình ảnh phiếu giao (multi-file, ≥1, max 10)
│                        UPLOAD on each pick:
│                            supabase.storage.upload(
│                              `temp/${session_id}/slip_${row}_${n}.{ext}`, file)
│                        Store paths in form state
│
├─ Step 3: Section II — Thông Tin Vận Chuyển
│         ├─ Khung giờ radio: 07-09 | 09-11 | 13-15 | 15-17 (required)
│         ├─ Ghi chú (optional, free text up to 500 chars)
│         └─ Ghi chú giao hàng (Atino notice — read-only display)
│
├─ Step 4: Submit
│         │
│         ├─ Client Zod validation → fail → inline errors
│         └─ PASS:
│                 POST Edge Function: /functions/v1/finalize_booking
│                 Headers: Authorization: Bearer {supplier_jwt}
│                 Body: {
│                   warehouse_id, time_slot, ghi_chu, delivery_note, session_id,
│                   items: [{ product_code, process_code, delivery_round,
│                             is_final_round, quantity_booked,
│                             vat_temp_path, slip_temp_paths }]
│                 }
│                 │
│                 Edge Function (service role):
│                 ├─ Verify JWT; extract supplier_id, supplier_account_id
│                 ├─ Verify supplier_account.status = 'active'
│                 ├─ INSERT bookings
│                 │       Triggers fire:
│                 │         set_booking_delivery_date() → delivery_date (N+1 or N+2)
│                 │         generate_booking_code()     → "2026-05-04-GC01-3434657"
│                 │       Returns: id, booking_code, booking_token, delivery_date
│                 ├─ INSERT booking_items (one per PO row)
│                 │       DB check: delivery_round=1 → vat_invoice_url NOT NULL
│                 ├─ Move storage files:
│                 │       temp/${session_id}/* → ${booking_id}/${item_id}/${filename}
│                 ├─ INSERT booking_item_photos (one per slip photo per item)
│                 ├─ UPDATE booking_items.vat_invoice_url to final paths
│                 ├─ INSERT notification
│                 │       { recipient='lethientinh', event='booking_submitted',
│                 │         message='Có booking mới từ [supplier_name]',
│                 │         booking_id }
│                 └─ Return { booking_code, booking_token, delivery_date }
│
├─ Step 5: Confirmation Screen → /booking/:token/confirmation
│         ├─ Large QR code (qrcode.react):
│         │       Encodes: https://[app-host]/booking/{booking_token}
│         ├─ "Mã đăng ký: 2026-05-04-GC01-3434657"
│         ├─ "Loại đăng ký: Giao theo đơn hàng (Outright)"
│         ├─ Print button
│         └─ Link: "Xem lịch sử đặt hàng" → /my-bookings
│
└─ ERROR PATHS
          ├─ Supplier account not active: "Tài khoản chưa được kích hoạt"
          ├─ File upload fail: per-file retry; submit disabled until all uploads done
          ├─ Edge Function 5xx: toast + preserve form state + allow retry
          └─ DB constraint fail (missing VAT): "Vui lòng tải lên hóa đơn VAT cho lần giao 1"
```

## FLOW A2 — Supplier Views Booking History

```
Supplier logs in → /my-bookings
│
├─ Load Bookings
│       GET  RPC: get_my_bookings(supplier_account_id, filters)
```

## FLOW D — Reviewer Dashboard (lethientinh)

```
Login → /reviewer
│
├─ Step 1: Load IN PARALLEL
│         ├─── Pending Bookings (polls every 30s)
│         │       GET supabase: SELECT b.*, s.name, w.name
│         │                     FROM bookings b
│         │                     JOIN suppliers s ON s.id = b.supplier_id
│         │                     JOIN warehouses w ON w.id = b.warehouse_id
│         │                     WHERE b.status = 'pending'
│         │                     ORDER BY b.delivery_date ASC, b.submitted_at ASC
│         │       TanStack Table: booking_code | supplier | delivery_date | time_slot | PO count
│         │
│         └─── Notification Bell
│                 GET supabase: SELECT * FROM notifications
│                               WHERE recipient_id = 'lethientinh' AND is_read = false
│
├─ Step 2: Open Booking → Review Modal
│         GET supabase: SELECT bi.*, array_agg(p.storage_path)
│                       FROM booking_items bi
│                       LEFT JOIN booking_item_photos p ON p.booking_item_id = bi.id
│                       WHERE bi.booking_id = $id
│                       GROUP BY bi.id
│         For each photo: storage.createSignedUrl(path, 3600)
│         Modal: PO list with thumbnails, delivery round, quantity, VAT invoice link
│
├─ Step 3: Per Item Action
│         │
│         ├─── Confirm
│         │       POST RPC: confirm_booking_item(item_id, 'lethientinh')
│         │           UPDATE booking_items SET status='confirmed', ...
│         │           CALL transition_booking_status(booking_id)
│         │               → IF any confirmed: booking.status = 'confirmed',
│         │                                   confirmed_by = 'lethientinh', confirmed_at = now()
│         │           INSERT notification to supplier:
│         │               "Đơn hàng [code] đã được xác nhận (một phần hoặc toàn bộ)"
│         │
│         └─── Reject
│                 POST RPC: reject_booking_item(item_id, reason, 'lethientinh')
│                     UPDATE booking_items SET status='rejected', reject_reason=$reason
│                     CALL transition_booking_status(booking_id)
│                         → IF all rejected: booking.status = 'rejected'
│                     INSERT notification to supplier:
│                         "Đơn hàng [code] đã bị từ chối: [reason]"
│
├─ Step 4: Amendment Requests
│         Tab or section in dashboard showing booking_amendments WHERE status='pending'
│         Reviewer reads request_note, then:
│         ├─ Approve: UPDATE booking_amendments SET status='approved'
│         │           (booking remains; supplier manually re-submits or edits outside system)
│         │           INSERT notification to supplier: "Yêu cầu chỉnh sửa được chấp thuận"
│         └─ Deny:    UPDATE booking_amendments SET status='denied', reviewer_note=$note
│                     INSERT notification to supplier: "Yêu cầu chỉnh sửa bị từ chối: [note]"
│
└─ Mark notification read
          PATCH supabase: UPDATE notifications SET is_read=true WHERE id=$id
```

## FLOW E — Receiver Scan (lethiendung)

```
Login → /receiver
│
├─ Step 1: Scan or Input
│         ├─── Camera QR scan (@zxing/browser)
│         │       Decodes URL → extract booking_token
│         └─── Manual input: booking_code (e.g. 2026-05-04-GC01-3434657)
│
├─ Step 2: Load Booking
│         GET supabase: SELECT b.*, s.name, w.name
│                       FROM bookings b
│                       JOIN suppliers s, warehouses w
│                       WHERE b.booking_token = $token  OR  b.booking_code = $code
│         │
│         ├─ NOT FOUND     → "Mã booking không hợp lệ"
│         ├─ status=pending  → "Booking chưa được xác nhận — vui lòng chờ"
│         ├─ status=rejected → "Mã booking không hợp lệ"
│         ├─ status=received → "Booking đã nhận hàng trước đó"
│         └─ status=confirmed →
│                 GET supabase: SELECT * FROM booking_items
│                               WHERE booking_id=$id AND status='confirmed'
│                 Render: PO table with [Số lượng nhận] input per row
│                         + [Thêm ảnh] per row for discrepancy photos
│
├─ Step 3: Receiver Inputs Actual Quantities
│         Per confirmed item: quantity_received (integer ≥ 0)
│         Optional per item: upload discrepancy photo
│             UPLOAD: supabase.storage.upload(`${booking_id}/${item_id}/discrepancy_${n}`, file)
│
└─ Step 4: Submit
          POST RPC: receive_booking(booking_token, quantities_json, 'lethiendung')
          │
          ├─ Verify booking.status = 'confirmed'
          ├─ For each item:
          │       UPDATE booking_items SET quantity_received = $qty
          │       IF qty ≠ quantity_booked:
          │           INSERT discrepancy_log {
          │             booking_item_id, quantity_booked, quantity_received,
          │             difference = qty - quantity_booked, recorded_at = now()
          │           }
          ├─ INSERT booking_item_photos (discrepancy, photo_type='discrepancy') if any
          ├─ UPDATE bookings SET
          │       status='received', received_by='lethiendung', received_at=now()
          ├─ INSERT notification to supplier:
          │       "Hàng đã được nhận [booking_code]"
          └─ INSERT notification to manager:
                  IF any discrepancies: "Có chênh lệch số lượng tại booking [code]"
                  ELSE: "Booking [code] nhận hàng thành công"

          UI: Show receive summary — per-item comparison table
              Discrepancy rows highlighted:
              "Số lượng thực nhận khác booking — NCC vẫn bị tính trễ hạn"
```

## Notification Delivery Flow

```
Any server action that creates a notification:
│
├─ INSERT notifications {
│     recipient_type, recipient_id, event_type,
│     message (Vietnamese), booking_id, is_read=false, created_at=now()
│  }
│
On authenticated pages (all roles):
│
├─ NotificationBell polls every 60s:
│       GET supabase: SELECT COUNT(*) FROM notifications
│                     WHERE recipient_id=$me AND is_read=false
│       Shows unread count badge on bell icon
│
├─ User clicks bell → NotificationPanel slides in:
│       GET supabase: SELECT * FROM notifications
│                     WHERE recipient_id=$me
│                     ORDER BY created_at DESC LIMIT 50
│       List: icon | message | relative timestamp
│       Click notification → navigate to relevant booking or admin page
│       → PATCH: UPDATE notifications SET is_read=true WHERE id=$id
│
└─ "Đánh dấu tất cả đã đọc"
          PATCH supabase: UPDATE notifications SET is_read=true
                          WHERE recipient_id=$me AND is_read=false
```

## Storage Lifecycle

```
Pre-submit (supplier uploads during form fill):
  supabase.storage.upload('booking-attachments/temp/{session_id}/{filename}')
  ↓ path stored in form state only (not in DB yet)

finalize_booking Edge Function:
  storage.move('temp/{session_id}/*', '{booking_id}/{item_id}/*')
  INSERT booking_item_photos.storage_path = final path

Read (reviewer / manager viewing photos):
  supabase.storage.createSignedUrl(path, 3600)
  → <img src={signedUrl} />   (URLs expire after 1 hour)

Cleanup:
  cleanup_temp_uploads Edge Function (cron, hourly):
  DELETE /temp/* older than 24 hours

Receiver discrepancy photos:
  Uploaded during FLOW E directly to final path:
  supabase.storage.upload('{booking_id}/{item_id}/discrepancy_{n}.{ext}')
  INSERT booking_item_photos (photo_type='discrepancy')

Future migration to GCS (when storage capacity demands it):
  storage_path column stores 'gcs://{bucket}/{path}' prefix
  URL resolver in shared/lib/storageUtils.ts generates correct signed URL
  Old files stay on Supabase; new files go to GCS
  No schema change required
```
