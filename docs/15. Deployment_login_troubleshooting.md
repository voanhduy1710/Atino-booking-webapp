# Deployment Login Troubleshooting

## Incident

Staff account `voanhduy1710` with password `voanhduy1710` worked locally but failed in the deployed web app.

The first deployed symptom was:

```text
JSON.parse: unexpected character at line 1 column 1 of the JSON data
```

After improving client-side API parsing, the real backend response became visible:

```text
Sai ten dang nhap hoac mat khau
```

## Root Cause

Local development loaded `VITE_STAFF_USERS` from `.env`, where the staff account JSON was valid.

Cloud Run received the staff users through `gcloud run deploy --set-env-vars`. Passing raw JSON through PowerShell and `gcloud` stripped JSON quotes, so Cloud Run received malformed data similar to:

```text
[{username:voanhduy1710,password_hash:...,role:admin}]
```

The backend expects valid JSON, so it could not parse staff users. Because no staff user matched, login fell through to supplier login and returned `401`.

## Fix

Staff users are now passed to Cloud Run as base64:

```powershell
$STAFF_USERS = $envVars["VITE_STAFF_USERS"]
$STAFF_USERS_B64 = [Convert]::ToBase64String([System.Text.Encoding]::UTF8.GetBytes($STAFF_USERS))
```

`deploy.ps1` sends `STAFF_USERS_B64`, and `server/routes/auth.ts` decodes it before parsing JSON:

```ts
const raw = process.env.STAFF_USERS_B64
  ? Buffer.from(process.env.STAFF_USERS_B64, 'base64').toString('utf8')
  : (process.env.STAFF_USERS ?? process.env.VITE_STAFF_USERS)
```

The API client also now reads response text before parsing JSON, so HTML or nginx errors produce useful messages instead of raw browser `JSON.parse` errors.

## Runtime Change

Cloud Run now runs the compiled Express server instead of `tsx/esm` at runtime:

```text
node /app/dist-server/index.js
```

The Docker build compiles the server with:

```text
npm run server:typecheck && npx tsc -p tsconfig.server.json
```

This makes production startup more deterministic and avoids depending on the TypeScript runtime loader inside Cloud Run.

## Verification

After redeploying, these checks passed:

```text
GET  /api/health       -> 200 { "status": "ok" }
POST /api/auth/login   -> 200 role: "admin", username: "voanhduy1710"
```

If the browser still shows an old login failure after deploy, hard refresh the page to clear cached frontend chunks.

## Notes

Cloud Run can briefly return `502 Bad Gateway` during cold start because nginx may accept traffic before Express is ready on port `3001`. Wait for the Express startup log before judging the API as unhealthy:

```text
INFO: Express server started {"port":3001}
```
