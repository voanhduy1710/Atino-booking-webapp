## Features

| Term | What it does |
|------|-------------|
| **30-min undo window** / **Hoàn tác** | After a reviewer confirms or rejects an item, they have 30 minutes to revert it back to pending. Button shows "Hoàn tác (Xp)" with minutes remaining. DB: `reviewed_at` on `booking_items`; RPC: `revert_booking_item`. |
| **Amendment** / **Yêu cầu điều chỉnh** | A supplier's request to change (update) or cancel (recall) an existing booking. Stored in `booking_amendments` table. Reviewed by warehouse staff in the amendment panel. |
| **Recall** / **Huỷ booking** | An amendment of type `recall` — supplier requests full cancellation. |
| **Partial approval** / **Duyệt một phần** | A booking where some items are confirmed and some are still pending. Derived status: `partially_approved`. |
| **Partial rejection** / **Từ chối một phần** | A booking where some items are rejected and others are not all confirmed. Derived status: `partially_rejected`. |
| **Derived status** | Booking status computed from item-level statuses via `deriveBookingStatus()`. The `status` column on `bookings` is the raw DB value; the derived status is what's displayed. |
| **Delivery note** / **Phiếu giao** | Photo attached to a PO row (slip/phiếu giao hàng). Stored in `booking_item_photos` with `photo_type = 'slip'`. |
| **VAT invoice** / **Hóa đơn VAT** | PDF/photo attached to round-1 items. Stored as `vat_invoice_url` on `booking_items`. |
| **Admin view-as** | Admin can view booking history as any supplier. Route: `/admin/view-as`. |

## Statuses

### Booking statuses (`BookingStatus`)

| Value | Display | Meaning |
|-------|---------|---------|
| `pending` | Chờ xác nhận | All items pending |
| `partially_approved` | Duyệt một phần | Some confirmed, rest pending |
| `partially_rejected` | Từ chối một phần | Some rejected, rest not all confirmed |
| `confirmed` | Đã xác nhận | All items confirmed |
| `rejected` | Đã từ chối | All items rejected |
| `received` | Đã nhận hàng | Goods received at warehouse |
| `cancelled` | Đã huỷ | Booking cancelled |

### Booking item statuses

| Value | Meaning |
|-------|---------|
| `pending` | Not yet reviewed |
| `confirmed` | Reviewer approved |
| `rejected` | Reviewer rejected |
| `received` | Goods physically received |

## Notification Event Types

| `event_type` | Who receives | Trigger |
|-------------|-------------|---------|
| `booking_submitted` | Staff | New booking submitted by supplier |
| `booking_confirmed` | Supplier | Reviewer confirms a booking item |
| `booking_rejected` | Supplier | Reviewer rejects a booking item |
| `amendment_requested` | Staff | Supplier submits amendment request |
| `amendment_approved` | Supplier | Staff approves supplier's amendment |
| `amendment_denied` | Supplier | Staff denies supplier's amendment |

## Backend

| Term | Details |
|------|---------|
| **Express backend** | Node.js/Express server at `server/`, proxied via `/api/*`. Port 3001 in dev. |
| **Booking submit endpoint** | `POST /api/booking` — creates booking + items + photos + notifies staff. |
| **GCS upload endpoint** | `POST /api/upload` — uploads photos to Google Cloud Storage. |
| **Supabase** | PostgreSQL DB + auth (for supplier account RPCs) + storage not used (GCS instead). |
| **RPC** | Supabase database function called via `supabase.rpc(...)`. Used for booking actions that need atomicity. |

### Key RPCs

| RPC | What it does |
|-----|-------------|
| `confirm_booking_item` | Sets item status = confirmed, stamps `reviewed_at`, updates booking status |
| `reject_booking_item` | Sets item status = rejected + reason, stamps `reviewed_at`, updates booking status |
| `revert_booking_item` | Reverts confirmed/rejected item back to pending (within 30-min window) |
| `request_booking_amendment` | Supplier submits amendment; notifies staff |
| `resolve_booking_amendment` | Reviewer approves/denies amendment |
| `transition_booking_status` | Internal — recomputes booking status from item statuses |
| `admin_delete_booking` | Hard-deletes a booking (admin only) |
